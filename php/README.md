# PHP-бэкенд форм PEMO Pumps

Два обработчика форм сайта — заявка (`/contacts`) и отзыв (`/reviews`) —
плюс общий конфиг и вспомогательные функции.

## Структура

```
php/
  config.php        ← единственный параметр, который обычно нужно менять: mail_to
  lib/helpers.php    CORS, rate-limit, отправка почты, CSV-лог
  send-lead.php      обработчик формы заявки
  send-review.php    обработчик формы отзыва
  storage/           CSV-бэкап заявок и файлы rate-limit (создаётся сам)
```

## Деплой на хостинг (PHP 8.5 + ionCube)

1. `npm run build` в корне проекта → получаете папку `dist/`.
2. На хостинг в `public_html` (или его аналог) загружаете:
   - **содержимое** `dist/` (index.html, assets/, images/, .htaccess) — в корень;
   - папку `php/` — тоже в корень, рядом с `index.html`, чтобы получился путь
     `public_html/php/send-lead.php`.
3. Откройте `php/config.php` и при необходимости поменяйте `mail_to`
   и `allowed_origins` (добавьте туда реальный домен сайта).
4. Проверьте, что PHP на хостинге не блокирует функцию `mail()`
   (на большинстве shared-хостингов она работает из коробки).
5. Права на папку `php/storage/` — обычная запись для веб-сервера (755/775).

`.htaccess` в корне (из `public/.htaccess`) делает две вещи:
- отдаёт `index.html` на все маршруты React Router (`/catalog`, `/about`…),
  не трогая `/php/...`;
- закрывает прямой доступ к `.csv`.

## Если письма уходят в спам

`mail()` с shared-хостинга нередко попадает в спам у Gmail — это ограничение
самого способа отправки, а не кода. Способы исправить, по возрастанию
трудозатрат:

1. Указать в `config.php` `mail_from` в **вашем** домене (не gmail.com) —
   уже сделано по умолчанию (`no-reply@pemopumps.ru`).
2. Настроить SPF-запись для домена хостинга (`v=spf1 include:<хостинг> ~all`) —
   делается в DNS, не в коде.
3. Перейти на отправку через SMTP вместо `mail()` — например, через
   PHPMailer и почтовый ящик на этом же домене или через сервис типа
   Yandex 360 / SendPulse / Postmark. Меняется только функция
   `pemo_send_mail()` в `lib/helpers.php`, остальной код обработчиков
   трогать не нужно.

## Локальная разработка

Фронтенд по умолчанию шлёт запросы на относительный путь `/php/...`,
что работает, когда сайт и `/php` на одном домене (как в проде).
Для локальной разработки (Vite на `localhost:5173`, PHP — на реальном
хостинге) создайте `.env`:

```
VITE_API_BASE=https://pemopumps.ru
```

и добавьте `http://localhost:5173` в `allowed_origins` в `config.php`
(уже добавлено по умолчанию).

Проверить обработчики локально без Vite:

```bash
cd php
php -S 127.0.0.1:8899
curl -X POST http://127.0.0.1:8899/send-lead.php \
  -H "Content-Type: application/json" \
  -d '{"name":"Тест","contact":"test@example.com","message":"Проверка"}'
```

(Встроенный сервер `php -S` не читает `.htaccess`, поэтому защита
`php/storage/` локально не сработает — на Apache-хостинге сработает.)
